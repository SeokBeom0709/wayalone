# 트러블슈팅

개발하면서 실제로 겪은 문제입니다.

## 1. 빌드할 때 `Unable to delete directory build` 가 반복됨
- **원인**: 프로젝트가 OneDrive 동기화 폴더 안에 있어서 동기화가 빌드 산출물을 잠갔습니다.
- **해결**: 프로젝트를 동기화 폴더 밖(`C:\demo`)으로 옮겼습니다.

## 2. 수정했는데 친구 폰에는 예전 화면이 보임
- **원인**: 브라우저가 `app.js`, `app.css`를 캐시했습니다.
- **해결**: 정적 파일에 `?v=N` 버전을 붙이고 수정할 때마다 올립니다.

## 3. 평가를 저장하면 "Unexpected end of JSON input"
- **원인**: `201 Created`처럼 본문이 없는 응답을 항상 `res.json()`으로 읽고 있었습니다.
- **해결**: 공통 `api()` 함수가 본문이 비어 있으면 `null`을 돌려주게 했습니다. 계정 두 개로 실제 흐름을 끝까지 눌러 보다가 발견했습니다.

## 4. 주변 식당 API가 502
- **원인**: 카카오 앱에서 지도/로컬 서비스가 꺼져 있었습니다. 처음에는 응답 본문을 로그에 남기지 않아 원인을 알기 어려웠습니다.
- **해결**: 외부 API 오류 본문을 로그로 남기게 바꾼 뒤 원인을 찾아 콘솔에서 서비스를 켰습니다.

## 5. 숨겨야 할 "더 보기" 버튼이 계속 보임
- **원인**: `.block { display: block }` 규칙이 `hidden` 속성을 덮어썼습니다.
- **해결**: `[hidden] { display: none !important }`를 전역으로 추가했습니다.

## 6. 지도 타일에 "API KEY REQUIRED" 워터마크
- **원인**: 쓰던 무료 타일 서비스(CARTO)의 정책이 바뀌었습니다.
- **해결**: 지도 엔진을 공통 인터페이스 뒤로 빼서 공급자를 바꿔도 화면 코드는 그대로 두고, 네이버 지도를 기본으로 정했습니다.

## 7. 회원 상태에 새 값을 추가하면 기존 DB에서 실패할 상황
- **원인**: Hibernate가 enum을 MySQL/H2의 네이티브 `ENUM(...)` 컬럼으로 만듭니다. `ddl-auto=update`는 이미 있는 컬럼의 값 목록을 바꾸지 않아서, `WITHDRAWN`을 추가하면 기존 DB에는 저장할 수 없습니다. 확인해 보니 MySQL과 H2 모두 `enum('ACTIVE','BANNED','SUSPENDED')`였습니다.
- **해결**: 컬럼을 `@JdbcTypeCode(SqlTypes.VARCHAR)`로 선언하고, 기존 DB 두 개는 `ALTER TABLE`로 한 번 바꿨습니다.
- **배운 점**: 운영 DB는 `update`에 맡기지 말고 마이그레이션 도구(Flyway)로 변경 이력을 관리해야 합니다.

## 8. 로그인 실패 기록이 사라질 뻔함
- **원인**: 실패하면 `ResponseStatusException`을 던지는데, 이 예외가 `@Transactional`을 롤백시켜 방금 저장한 기록도 사라집니다.
- **해결**: `login()`에 `noRollbackFor = ResponseStatusException.class`를 적용했습니다. 실패 경로에는 다른 쓰기가 없다는 것을 확인했고, 실패 기록이 남는지 테스트합니다.

## 9. 탈퇴해도 예전 닉네임이 남음
- **원인**: 닉네임이 모집글, 신청, 후기, 문의 테이블에 복사 저장돼 있습니다.
- **해결**: 탈퇴 트랜잭션에서 네 테이블의 닉네임을 한꺼번에 바꾸고, 탈퇴 후 노출되지 않는지 테스트합니다.
